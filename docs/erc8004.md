# ERC-8004: registering Zolva

Zolva gets one identity in the ERC-8004 Identity Registry on Robinhood Chain. That gives it a verifiable listing with agent number, MCP, REST and x402 endpoints on 8004scan. Background and ranking are in `docs/integration-scan.md`. Kyte registered on Nov 8 as #22541, unverified and without x402.

## What is built

- `lib/erc8004.ts` holds the registration file (spec format `registration-v1`).
  - name, description, logo
  - services: web, MCP, REST, x402
  - `x402Support: true`, `supportedTrust: ["reputation"]`
- It is served at https://zolvaagent.app/.well-known/agent-registration.json through a rewrite to `app/api/erc8004/registration`.
- That URL is both:
  - the agentURI the registry stores, and
  - the spec's domain-verification file.

  One file covers both, so Zolva shows as verified, unlike Kyte.

## Steps (as planned; step 2 was done by the script instead of Blockscout)

1. **Deploy** the app so the file is live (needs the owner's go).
2. **Owner registers.** This is one transaction, about a few cents of ETH on Robinhood Chain.
   1. Open https://robinhoodchain.blockscout.com/address/0x8004A169FB4a3325136EB29fA0ceB6D2e539a432?tab=write_proxy
   2. Connect the wallet that should own Zolva's identity.
      - It becomes the NFT owner and the default `agentWallet`, the payment address in the registry.
      - Use a wallet you keep long term. Moving the NFT later clears `agentWallet`.
      - Not a live trading wallet.
   3. Open function 17, `register` (selector `0xf2c298be`, one `agentURI` string field), and paste: `https://zolvaagent.app/.well-known/agent-registration.json`
   4. Click Write, then confirm in the wallet.
3. **Send me the transaction hash.** I read the `agentId` from the `Registered` event, set `ERC8004_AGENT_ID` in `lib/erc8004.ts`, and redeploy. The file then carries `registrations: [{ agentId, agentRegistry: "eip155:4663:0x8004A169…a432" }]`.
4. **Check** the entry on 8004scan (verified, x402) and draft the tweet. It is a listing, never a partnership.
